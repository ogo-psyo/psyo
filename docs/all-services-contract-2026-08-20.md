# «Всё»: контракт продуктового фундамента

## Цель

Экран «Всё» показывает только реальные owner-scoped модули выбранной собаки. Карточка модуля обязана иметь собственное состояние, действие и источник данных.

## Источники истины

- Базовые данные собаки: `pets`, владелец — `ProfileService`.
- Напоминания и история выполнения: `reminders` + `reminder_events`, владелец — `ReminderService`.
- Привычки и отметки: `pet_habits` + `habit_checkins`, владелец — `HabitService`.
- Наблюдения здоровья: `pet_observations`, владелец — `HealthTimeline`.
- Сводка: вычисляемая проекция из перечисленных owner-scoped источников, владелец — `DogSummary`; собственных медицинских выводов не хранит.

## Состояния

### HabitService

- Привычка: `active | archived`.
- Отметка: неизменяемый факт с временем выполнения; повторная команда с тем же idempotency key не создаёт дубль.
- Ошибки: неизвестная собака, чужая собака, невалидное расписание, повторно использованный ключ с другим payload.

### HealthTimeline

- Запись: `active | deleted`; удаление обратимое через существующий lifecycle наблюдений.
- Тип записи остаётся фактом владельца, а не диагнозом или рекомендацией.

### DogSummary

- `empty`: есть только профиль собаки.
- `active`: есть факты хотя бы одного модуля.
- `attention`: есть просроченное напоминание; медицинские риски не вычисляются.

## Запрещено

- Требовать поле, которое не сохраняется и не используется как факт профиля.
- Показывать модуль, если за карточкой нет собственного состояния и действия.
- Генерировать план, медицинский вывод или породную рекомендацию без отдельного проверенного knowledge-сервиса.
- Использовать UI или localStorage как источник истины для Telegram-пользователя.

## Приёмка локального среза

1. Контрактные тесты сначала падают, затем проходят.
2. Все запросы изолированы по `owner_id` и `pet_id`.
3. Новый и активный пользователь имеют разные состояния «Всё».
4. На экране нет повторяющегося манифеста и декоративных счётчиков.
5. `npm run qa:local`, browser smoke и мобильные screenshots проходят до любого решения о deploy.
