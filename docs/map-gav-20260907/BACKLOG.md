# «Псё»: беклог обновления карты и «Гав»

Редакция: 7 сентября 2026 года. **29 задач: 16 P1, 12 P2, 1 P3.** Статус карточек: Backlog. Документ предназначен для постановки в разработку и дизайн.

**Целевое направление карты — переход на Яндекс API с сохранением всех текущих возможностей. Целевое визуальное направление — тёплый и выразительный «Псё»: собаки, авторские иллюстрации и характерные детали. Типографика и основная композиция сохраняются.**

DoR — Definition of Ready, условия начала задачи. DoD — Definition of Done, проверяемые критерии завершения. Здесь это критерии готовности конкретных изменений; незаполненные чекбоксы не означают, что соответствующей функции сейчас нет в production.

## Продуктовая рамка

- Карта, все действующие маршруты и способы построения/записи, слои, места, подборки, оба режима «Гав», все цели знакомств, отклики и связи сохраняются.
- «Вещи», «Всё», профиль, уход, наблюдения, документы, памятки, подписка и все ассистенты остаются доступны с действующими возможностями и точками входа.
- Сохраняются пользовательские данные, ссылки, права, выбранная собака, правила географической точности и согласия.
- Уже выполненный критерий подтверждается проверкой. Реализация переиспользуется; дублирующий раздел не создаётся.
- Любой предел нового API должен иметь решение, сохраняющее текущие возможности пользователя. Ограничения поставщика не становятся основанием сократить продукт.
- Визуальные изменения касаются оформления конкретных элементов карты и «Гав». Шрифты, типографическая шкала, основная сетка и композиция сохраняются. Локальные изменения порядка действий допускаются там, где они решают указанную в карточке UX-проблему.
- Все задачи относятся к работающему продукту. Проверки интеграции и регрессии сопровождают выпуск; функции продолжают работать до замены. Публикации и сообщения для проверки выполняются только в предназначенных для этого аккаунтах/окружениях.

## Общий DoR

Применяется вместе с DoR карточки. Для подготовительных и дизайн-задач результат исследования/дизайна является выходом задачи и не требуется заранее.

- [ ] Названы ответственный, ожидаемый результат и затронутые сценарии.
- [ ] Доступны нужные исходники/экраны/данные; отдельно отмечено, что уже работает и должно сохраниться.
- [ ] Завершены указанные зависимости либо есть проверенный согласованный контракт для параллельной реализации. Включение в production требует работоспособности всех необходимых зависимостей.
- [ ] Описаны необходимые для этой задачи состояния успеха, пустоты, ошибки и возврата; определён способ приёмки.

## Общий DoD

Применяется вместе с DoD карточки.

- [ ] Выполнены все применимые критерии карточки; приложены результаты проверки, а для визуальных изменений — сравнение на одинаковом содержимом.
- [ ] Сохранены затронутые действующие сценарии, данные, ссылки, права, контекст собаки и ассистенты.
- [ ] Пользователь видит фактический результат действия; ошибка не превращается в ложный успех или потерю ввода.
- [ ] Изменения сохранения, миграции, публикации и взаимодействия сторон проверены соответствующими интеграционными/регрессионными проверками. Для локальной визуальной правки достаточно целевого визуального и интерактивного прохода.
- [ ] Затронутые интерфейсы проходят применимую часть UX-01; новые API — применимую часть OPS-01.
- [ ] Обновлена необходимая документация: компоненты, схемы, статусы или настройки; известные ограничения записаны.
- [ ] Изменение кода включено в проверенную production-поставку по REL-01. До выпуска статус — Ready for release. Подготовительные и дизайн-карточки считаются Done после проверки перечисленных в них артефактов; это не означает, что дизайн уже внедрён.

P1 — сохранность, ясность критичных действий и обязательные работы перехода. P2 — удобство и визуальное качество. P3 — дополнительная возможность после основного обновления. Это приоритеты задач, а не оценки тяжести текущих дефектов. Сроки и story points не назначены без оценки репозитория и команды.

### GEO-01. Зафиксировать текущие сценарии и данные карты и «Гав»

**Приоритет:** P1 · **Ответственные роли:** Product + Frontend + Backend + QA · **Тип:** Подготовка реализации.

**Зависимости:** нет.

**Основание:** Рамка владельца продукта; ограничения повторного аудита.

**Результат:** Получить проверяемую исходную точку для переноса без потери работающих возможностей.

**Сделать:** Описать входы, режимы, состояния, API, модели и ссылки. Отдельно пройти обычную карту, места, подборки, непустые маршруты и реальные состояния «Гав», недоступные при повторном аудите.

**DoR**

- [ ] Доступны актуальный репозиторий, сборка и назначенные аккаунты для проверки; назван ответственный за продуктовые правила.
- [ ] Известны затронутые разделы; доступны прежние аудиты и текущий беклог.

**DoD**

- [ ] Составлена матрица «сценарий → вход → результат → данные/права → способ приёмки», включая все слои, ручные способы построения, запись, подборки и ассистентов.
- [ ] Зафиксированы правила двух режимов «Гав»: фильтры, цели, видимость, сроки сигналов, отклики, связи, ограничения и блокировки, если они предусмотрены продуктом.
- [ ] Зафиксированы поставщики карты/поиска/маршрутов, форматы координат, действующие ограничения и примеры старых записей/ссылок.
- [ ] Каждая уже выполненная часть этого беклога отмечена как подтверждённая; повторная разработка не назначена. Неизвестное помечено как вопрос, а не дефект.

### GEO-02. Подготовить подключение Яндекс API, условия и бюджет

**Приоритет:** P1 · **Ответственные роли:** Tech Lead + Product / владелец аккаунта · **Тип:** Интеграция.

**Зависимости:** [GEO-01](#geo-01).

**Основание:** Обсуждённое направление перехода на Яндекс.

**Результат:** Подключить набор сервисов, который покрывает весь текущий сценарий и разрешает нужную работу с данными.

**Сделать:** Выбрать JS API v3, поиск организаций, подсказки, геокодирование при необходимости и маршрутизацию. Зафиксировать географию, квоты, разрешённые поля и хранение.

**DoR**

- [ ] Названы целевые города/страны и владелец кабинета Яндекса; доступны сведения о текущей нагрузке либо явно обозначенные расчётные сценарии.
- [ ] Из GEO-01 известны данные, которые продукт сохраняет, изменяет, показывает и передаёт по ссылкам.

**DoD**

- [ ] Есть таблица «пользовательский сценарий → сервис → ключ/доступ → квота → правила хранения/показа → стоимость» и выбран подходящий вариант лицензии.
- [ ] В бюджет включены подсказки, карточки мест и повторные расчёты маршрутов; зафиксированы численные лимиты расходов и ответственный за их контроль.
- [ ] Ключи настроены для нужных окружений и разрешённых доменов; серверные секреты не попадают в клиент, клиентские ключи имеют предусмотренные ограничения.
- [ ] На разрешённых реальных запросах подтверждены нужные поля поиска, пеший режим и ограничения маршрутов; расхождения с текущими возможностями имеют решение без их сокращения.

### GEO-03. Отделить данные «Псё» от картографического поставщика

**Приоритет:** P1 · **Ответственные роли:** Backend + Frontend · **Тип:** Интеграция и сохранность данных.

**Зависимости:** [GEO-01](#geo-01), [GEO-02](#geo-02).

**Основание:** MG-12.

**Результат:** Обеспечить замену поставщика с сохранением мест, маршрутов, подборок и существующих ссылок.

**Сделать:** Описать и реализовать минимальные адаптеры отображения, поиска и расчёта пути; сохранить внутренние идентификаторы и отделить данные поставщика от пользовательских.

**DoR**

- [ ] Известны текущие схемы, ссылки, форматы геометрии и условия хранения Яндекса.
- [ ] Определены операции, которые действительно различаются между поставщиками; согласован объём изменений схемы.

**DoD**

- [ ] Карточка места и состав подборки используют устойчивые внутренние ID; ссылки поставщиков хранятся отдельно с указанием источника.
- [ ] Владение, доступ, заметки, порядок и связи объектов сохраняются при смене поставщика; отсутствие соответствия в Яндексе не удаляет исходный объект.
- [ ] Преобразования широты/долготы, единиц расстояния/времени и геометрии проверены на известных точках и маршрутах.
- [ ] Адаптеры возвращают различимые успех, пустой ответ, ошибку и превышение квоты; есть способ переключения реализации без изменения продуктовых сценариев.

### GEO-04. Перенести отображение карты на Яндекс JS API v3

**Приоритет:** P1 · **Ответственные роли:** Frontend · **Тип:** Миграция.

**Основание:** MG-06/07/12.

**DoR**

- [ ] Записаны версия, состав релиза, результаты проверки и показатели после выпуска; при нарушении порогов выполнен предусмотренный возврат.
- [ ] Запланированные функции не выдаются за выпущенные; статус Done ставится после production-проверки, а выполненное только в ветке отмечается Ready for release.


## Дополнительное развитие маршрутов

### GEO-15. Добавить прогулку на выбранную продолжительность

**Приоритет:** P3 · **Ответственные роли:** Product + Design + Frontend + Backend · **Тип:** Дополнительное развитие.

**Зависимости:** [GEO-06](#geo-06), [GEO-11](#geo-11), [GEO-13](#geo-13).

**Основание:** Направление маршрутов из повторной оценки.

**Результат:** Получить редактируемый вариант прогулки под доступное время.

**Сделать:** Выбор начала, желаемой длительности и доступных предпочтений; подбор промежуточных точек и возвращение к началу.

**DoR**

- [ ] Определены модель времени, учёт остановок, допустимое отклонение от запроса и источники предпочтений; численные допуски записаны до реализации.
- [ ] Подготовлены контрольные случаи для целевых городов и предел числа расчётов/стоимости одной генерации.

**DoD**

- [ ] Вариант возвращается к началу и попадает в заранее заданный допуск по расчётному времени либо сообщает, что подходящего варианта нет.
- [ ] Маршрут можно просмотреть, отредактировать и сохранить обычным редактором; все ручные способы доступны.
- [ ] Учитываются только подтверждённые предпочтения; не обещается безопасность/доступность места без данных.
- [ ] Время обозначено как оценка, а число запросов ограничено бюджетом; ошибка сохраняет введённые параметры.
- [ ] Эта функция выпускается отдельным дополнением и не является условием работы существующих маршрутов или перехода на новую подложку.


## Обязательные проходы приёмки

В каждом релизе выполняются затронутые строки. При переключении основной карты обязательны все географические цепочки и связанные сценарии «Гав»/ассистентов. Полная матрица GEO-01 дополняет этот список всеми текущими возможностями.

| Сценарий | Проверяемый результат |
|---|---|
| Открыть карту со старым пустым и непустым черновиком | Обычная карта доступна; полезная работа сохраняется и продолжается |
| Поиск → место → возврат | Правильный объект; сохранены запрос, область, фильтры и положение списка |
| Быстро менять запрос/область | Последний ответ соответствует текущему запросу; устаревший не перезаписывает его |
| Маршрут через несколько мест → вернуть к началу → сохранить | Пешая геометрия проходит точки в нужном порядке; сохранённый объект открывается |
| Число точек больше лимита одного запроса поставщика | Текущий пользовательский сценарий сохранён; точки не отбрасываются |
| Изменить слой во время редактирования/записи | Сохраняются геометрия, текущий шаг, запись и выбранное место |
| Прервать геолокацию/сеть → вернуться | Понятное состояние, сохранённая работа, отсутствие вымышленного участка пути |
| Старая ссылка на место/подборку/маршрут | Открывается исходный пользовательский объект с действующими правами |
| Одно место в двух подборках → удалить из одной | Вторая подборка и общая история не повреждены |
| Подборка → выбрать места → собрать прогулку | Получен редактируемый маршрут; исходная подборка не изменена |
| Открыть «Гав» без координат / с ручным районом | Понятен центр поиска; отсутствие геоданных не выглядит как достоверный ноль |
| Сменить собаку, режим и фильтры → вернуться | Не смешаны данные собак; сохранён предусмотренный контекст каждого режима |
| Сохранить скрытую анкету → опубликовать → скрыть | Видимость и результат соответствуют действию, данные сохранены |
| Создать Гав → повторить запрос → завершить/дождаться срока | Нет непредусмотренного дубля; статус и срок согласованы с сервером |
| Отклик с обеих сторон, включая параллельные действия | Согласованное конечное состояние и доступные действия |
| Поделиться местом/маршрутом в разрешённом общении | Предпросмотр и полученный объект совпадают; видимость не расширена |
| Открыть ассистента из карты/«Гав» → выполнить текущий сценарий → вернуться | Сохранены контекст, действующие возможности и навигация |
| Карточка с фото / без фото / длинным именем / ошибкой | Единый визуальный характер, читаемость и доступное основное действие |
| Миграция → новая запись → возврат версии | Старые и новые данные читаются, ссылки и права сохранены |

## Решения по Яндекс API, которые фиксируются в GEO-02

Выбор Яндекса — целевое направление этого беклога. Подключение карты, поиска и маршрутов нужно описать по отдельным сервисам и доступам. В документации JS API поиск использует настройку ключа Search API. [Поиск по карте](https://yandex.ru/maps-api/docs/js-api/object/geosearch/index.html).

Для маршрутов требуется явный пеший режим. У актуального HTTP API есть предел количества точек; формат координат нужно сверять отдельно от клиентской карты. Ограничения и возможности платного тарифа фиксируются в конфигурации и приёмке GEO-06, а не зашиваются в продуктовые обещания. [Формат запроса маршрутизации](https://yandex.ru/maps-api/docs/router-api/request.html).

Условия бесплатного использования ограничивают хранение и изменение данных, полученных средствами API. В GEO-02 нужно выбрать условия под фактическое хранение мест и маршрутов; собственные записи пользователя и данные поставщика описываются раздельно. [Условия использования](https://yandex.ru/dev/commercial/doc/ru/).

Источники проверены 7 сентября 2026 года. Цены и лимиты перед подключением фиксируются в GEO-02 по выбранному договору; в этом документе отсутствует вымышленная оценка стоимости всей системы.
