# Псё — ценность и сценарии экрана «Карта»: DoR / DoD

Дата: 7 сентября 2026. Основание: обратная связь Руслана 16317–16323.

**Статус: спецификация для реализации. Не отчёт о внедрении.** Проверена по коду выпущенной версии `80e102598e3cbfe6e8d8880cce60a41e122099d6`. Ниже новые требования отделены от существующих возможностей и непроверенных предположений. Чекбоксы — критерии будущей приёмки, а не доказательство отсутствия функций.

## 1. Ценность и границы

Карта помогает **выбрать место, подготовить прогулку и использовать её результат снова**. Экран не считается полезным только потому, что открыл карту, перевёл фокус в поиск или показал форму.

| Намерение | Полученная ценность | Что НЕ является завершением |
|---|---|---|
| Найти место для конкретной цели | Выбрано реальное место в понятной области; пользователь понимает доступные сведения и может сохранить его или включить в прогулку | Фокус в строке поиска, список произвольных сохранённых записей |
| Подготовить прогулку | Сохранён маршрут с остановками и актуальным путём, открываемый перед выходом | Добавленная пробная строка, линия без объяснения способа построения |
| Записать прогулку | Запись завершена и сохранена с фактической геометрией, длительностью и пропусками; доступна для повторного использования | Нажатие «Начать», скрытая или зависшая запись |
| Вернуться к своему плану | Найдено ранее сохранённое; можно продолжить, повторить или изменить без повторного ввода | Счётчик сохранённых объектов без входа в объект |
| Отметить опасность | Сохранено предупреждение в выбранном месте с понятной видимостью и возможностью управления | Переход в поиск или неопределённая публикация |

**Сохраняется:** основная композиция карта/рабочая область, матовые поверхности, мягкие значки и короткие анимации; все ручные способы построения, запись, слои, подборки, старые ссылки, права, выбранная собака и ассистенты. Все остальные разделы и оба режима «Гав» остаются доступны. Существующий сценарий нельзя убрать ради чистоты первого экрана.

**Не входит в эту спецификацию:** миграция на Яндекс, новые платные сервисы, новый визуальный перезапуск, перепроектирование всего «Гав», автоматическая публикация мест или маршрутов. Генерация новой прогулки по времени остаётся отдельной GEO-15; подбор записанного круга нельзя представлять такой генерацией. Рамка дополняет исходный беклог GEO/GAV/VIS, не заменяет его.

## 3. Контракт экрана и состояний

Это функциональная спецификация, не готовый визуальный макет. До реализации изменяемых поверхностей нужен связанный показ перечисленных состояний на одних данных, включая низ экрана.

### Первый вход и приоритет

1. При активной записи — видимый статус и управление записью; экран не начинает её заново.
2. При черновике — предложение продолжить; обычная карта остаётся доступна, чужая новая задача не перезаписывает черновик.
3. В остальных случаях — видимая область карты и содержание выбранного рабочего раздела. Наличие собаки/сохранённых данных не является условием просмотра публичных мест.

| Рабочая область | Основное содержание | Контекстные действия |
|---|---|---|
| Места | Места в обозначенной области; категории — фильтры выдачи, не отдельные пустые экраны | Выбрать место; изменить область/фильтр |
| Выбранное место | Название, категория, адрес/область, источник, известные условия, статус сохранения | «В маршрут», «Сохранить»; возврат в ту же выдачу |
| Прогулки | Активная запись или черновик; при их отсутствии — начать запись либо построить маршрут | Управление текущей работой; подбор прежнего круга — вторично |
| Конструктор | Те же остановки, что на карте, в заданном порядке; актуальность расчёта | Добавить с карты/из поиска/подборки, изменить порядок, рассчитать, сохранить |
| Сохранённое | Свои маршруты и подборки с входом в объект | Открыть, повторить, изменить; существующие операции сохраняются |
| Выбранная точка | Положение и доступная точность | Добавить остановку или начать предупреждение здесь |

Поиск существует **в одном месте** и допускает разные контексты результата: обзор места либо выбор остановки. При выборе для конструктора результат возвращается в тот же план. Ни вкладка, ни категория не могут считаться реализованными одним переводом фокуса в поиск.

### Данные и источник истины

- `AreaContext`: границы, источник выбора (геолокация / вручную / сохранённая камера), ревизия. Центр карты не выдаётся за реальное местоположение человека.
- `PlaceQuery`: область, фильтр или текст, ревизия. Ответ содержит источник, время получения и признак ограниченной/неполной выдачи. Это требуемый контракт, не утверждение о текущем API.
- `SelectedPlace`: устойчивый источник/ID, координаты либо область точности, сведения с происхождением. Пользовательская заметка отделена от внешних данных.
- `RouteDraft`: выбранная собака, остановки, способ построения, ревизия, геометрия и ревизия расчёта. Редактирование остановок делает расчёт неактуальным; это не ошибка сохранения.
- `SavedRoute` и `MapLibrary`: для авторизованного владельца — существующие серверные модели и права. Гостевое локальное сохранение не называется сохранением в аккаунте.
- `Recording`: текущая запись с сегментами/пропусками и состоянием GPS. Вход на экран и смена слоя не создают новую запись.

**Выдача:** нет области → область выбрана → загрузка → результаты / пусто / ошибка / квота. После перемещения карты старая выдача обозначена как относящаяся к прежней области до явного обновления. Запоздавший ответ не заменяет актуальный.

**План:** черновик → изменён → расчёт → готов / нет пути / ошибка / лимит → сохранение → серверный успех / ошибка с сохранённым вводом → повторное открытие. Прямая линия никогда не заменяет пеший расчёт без явного перехода в ручной режим.

## 4. Общие DoR и DoD

### Общий DoR — можно начинать реализацию карточки, когда

- [ ] Указаны исполнитель и проверяющий; для продуктового решения — вопрос и тот, кто его принимает. В этой спецификации указаны требуемые роли, конкретные назначения пока не сделаны.
- [ ] Подтверждены вход, конечный результат, затронутые сущности и существующие функции для переиспользования.
- [ ] Закрыты зависимости карточки либо зафиксирован проверяемый контракт параллельной работы.
- [ ] Есть состояния успеха, пустоты, ошибки, возврата и применимые геолокация/квота/гость; для UI — связанный макет этих состояний.
- [ ] Доступны контрольные данные и безопасное окружение. Для двусторонней/production-записи назначены тестовые аккаунты, а не аккаунты реальных пользователей.

Для исследовательской карточки макет и готовый API не требуются заранее: её результат — как раз проверенный контракт. Неготовность геовыдачи не блокирует отдельное исправление ложной подписи или проверку сохранности маршрута.

### Общий DoD — карточка реализована и принята, когда

- [ ] Выполнены все применимые критерии карточки; каждому приложено наблюдаемое доказательство, а не только число тестов.
- [ ] Пройден путь от намерения до результата и повторного использования; ошибки не теряют ввод и не выглядят успехом.
- [ ] Сохранены данные, права, ссылки, контекст собаки, ручные режимы, слои и ассистенты.
- [ ] На 320×740, 390×844, 1280×720 в Chromium/WebKit доступны последние действия, нет непредусмотренной горизонтальной прокрутки; зоны нажатия не менее 44×44 CSS px.
- [ ] Клавиатура, фокус/возврат, сообщения статуса и уменьшенное движение работают. Карта/панель/клавиатура не перекрывают результат или действие.
- [ ] Проверены затронутые API/хранение/регрессии; для оформления достаточно целевого прохода, а не бессмысленного набора тестов на CSS.
- [ ] Дизайн-карточка закрывается артефактами; код до выпуска имеет статус Ready for release. Product Done — только после применимой production-приёмки. Непроведённая физическая проверка остаётся открытой.

## 5. Карточки

### MAP-01 — Честный и полезный первый вход

**Приоритет P1. Роли:** Product/Design + Frontend + QA. **Зависимости:** нет для исправления подмены; MAP-02 для географической выдачи. **Связь:** GEO-08/09, UX-01, VIS-03.

**Ценность:** понять, где я смотрю карту и какую текущую работу могу продолжить, без лишнего перехода в поиск.

**DoR**

- [ ] Сняты текущие состояния: новый пользователь, ручная область, отказ GPS, сохранённые объекты, пустой/непустой черновик, активная запись.
- [ ] Для каждого состояния определены основное содержание, основное действие и возврат; показана полная рабочая область.

**DoD**

- [ ] Убрана подмена «рядом» первыми сохранёнными записями. Собственные места, если показаны, явно обозначены своими и отфильтрованы по заявленной области.
- [ ] Нет повторного действия, которое только фокусирует уже видимый поиск. Доступ к самому поиску сохранён.
- [ ] Видны область и способ её изменения. Без GPS можно выбрать область вручную; отсутствие координат не показывается как «рядом ничего нет».
- [ ] Активная запись и полезный черновик доступны без обязательного открытия редактора и без перезаписи.
- [ ] До готовности MAP-02 интерфейс не изображает работающую выдачу мест. Исправление подписи само по себе не закрывает ценность поиска места.

**Приёмка:** пройти все шесть входных состояний, видео до первого полезного действия; сверить данные списка с областью. **Статус:** специфицировано, DoR реализации не подтверждён.

### MAP-02 — Реальные места в понятной области

**Приоритет P1. Роли:** Product + Backend/Frontend + QA. **Зависимости:** исследование источника — нет; реализация — результат исследования. **Связь:** GEO-01/05/10, OPS-01, без Яндекса.

**Ценность:** получить подходящие кандидаты без необходимости заранее знать название места.

**DoR исследования**

- [ ] Названы контрольные области и категории: минимум парк, площадка для собак, ветклиника; остальные действующие категории не исключаются.
- [ ] Для каждого контрольного объекта есть независимый проверяемый источник. Тип «парк» сам по себе не доказывает разрешение гулять с собакой.

**Выход исследования / DoR реализации**

- [ ] Проверен допустимый источник POI по области/категории: реальные ответы, ограничения показа/хранения, полнота, ошибки, стоимость и квоты. Существующий текстовый Nominatim-поиск не объявляется автоматически таким источником.
- [ ] Записаны точные лимиты области, результатов, частоты, тайм-аута и кэша; выбрано поведение при усечении. Числа должны следовать из проверки поставщика, а не быть выдуманы в дизайне.
- [ ] Есть контракт AreaContext/PlaceQuery и набор контрольных объектов: внутри, снаружи, на границе, без части данных. Если источника без новых расходов нет — зафиксирован блокер, а не фиктивная выдача.

**DoD**

- [ ] Выбор категории возвращает кандидатов в заданной области, не просто вставляет текст в поиск. Список и маркеры соответствуют одному ответу и имеют общую идентичность.
- [ ] Контрольные объекты внутри/снаружи обрабатываются по границам; ручная область работает без геолокации. Смена фильтра не оставляет результаты прежнего фильтра.
- [ ] Изменение камеры не запускает неограниченные запросы. «Искать в этой области» применяет новые границы явно; запоздавший ответ не подменяет их.
- [ ] Пусто, загрузка, квота и ошибка различимы. Для пустоты доступны явное изменение области/категории, для ошибки — повтор; скрытого расширения области нет.
- [ ] Неполная выдача не называется «все места»; число показанных не выдаётся за общее число объектов. Нет вымышленных рейтингов, расстояний или условий посещения.

**Приёмка:** контрактные/географические тесты + записанный реальный запрос к разрешённому источнику + сценарий выбора места. **Статус:** Ready for discovery по составу задачи; DoR реализации открыт до проверки источника и назначения ролей.

### MAP-03 — Выбрать место и получить результат

**Приоритет P1. Роли:** Design + Frontend/Backend + QA. **Зависимости:** текущий поиск/сохранённое уже могут дать вход; MAP-02 добавляет вход из геовыдачи. **Связь:** GEO-13, VIS-03.

**Ценность:** понять, подходит ли место, затем сохранить его на будущее или использовать в текущем плане.

**DoR**

- [ ] Определены разрешённые поля и источники, включая отсутствие данных про собак, фото или проверенный вход.
- [ ] Описаны возвраты из карты, поиска, подборки и выбора остановки; имеется пример сохранённого и несохранённого объекта.

**DoD**

- [ ] Первым видны название, категория, адрес/область и известные условия. «Нет данных» не превращается в «можно» или «нельзя с собакой».
- [ ] «В маршрут» добавляет выбранное место через подтверждение в тот же черновик; «Сохранить» показывает целевую подборку и подтверждённый результат.
- [ ] Повторное сохранение не дублирует объект/членство; отмена убирает последнее добавление, а не чужие заметки и другие подборки.
- [ ] При ошибке сохранения сохраняются выбор и ввод; повтор не создаёт дубль. У гостя честно обозначена граница локального/аккаунтного сохранения.
- [ ] После возврата восстановлены запрос, фильтры, камера, выделение и позиция списка. Приблизительная область не превращается в точную остановку без явного выбора точки.

**Приёмка:** два входа в одно место → сохранение с ошибкой/повтором → возврат → перезагрузка → открытие того же объекта. **Статус:** часть реализована; новая сквозная приёмка обязательна.

### MAP-04 — Собрать и повторно использовать прогулку

**Приоритет P1. Роли:** Frontend/Backend + QA, Design для непройденных состояний. **Зависимости:** существующая маршрутная модель; MAP-03 для входа из карточки. **Связь:** GEO-11, GEO-08, GEO-14; RV-01–03.

**Ценность:** получить план для реального следующего выхода, а не только нарисованный маршрут.

**DoR**

- [ ] Описаны начало, карта/поиск/подборка, порядок, круг, ограничения расчёта, старые ручные маршруты и запись GPS.
- [ ] Есть контракт остановок/геометрии/ревизии и назначенный тестовый аккаунт для настоящего сохранения.

**DoD**

- [ ] Собрать минимум три остановки, используя карту и конструктор; каждое добавление видно в одном списке и на карте. Названия и порядок не теряются при входе из подборки.
- [ ] Изменить порядок без drag-and-drop, удалить/отменить, вернуть к началу; переход между картой и редактором сохраняет черновик и выбранную собаку.
- [ ] Расчёт выдаёт актуальный путь, расстояние, оценку времени и известные ограничения; после изменения остановок прежний результат не сохраняется как актуальный.
- [ ] Нет пути/квота/слишком большая область/сбой сохраняют остановки. Ручной режим доступен явно; его линия не подписана пешим расчётом.
- [ ] Сохранить после пробного сбоя, перезагрузить, открыть из аккаунта: те же остановки, геометрия, заметка и видимость; повтор запроса не дублирует маршрут.
- [ ] Открыть перед прогулкой, видеть старт и весь путь, выгрузить совпадающий GPX. Повторное использование не перезаписывает оригинал без явного действия.

**Приёмка:** единая запись всего пути + API/БД-сверка на тестовом аккаунте; отдельно старый ручной маршрут и запись GPS. **Статус:** существенно реализовано, локальные доказательства есть; авторизованный production roundtrip не подтверждён.

### MAP-05 — Записать прогулку без потери результата

**Приоритет P1. Роли:** Frontend/Backend + QA на целевых устройствах. **Зависимости:** существующий механизм записи; не зависит от MAP-02. **Связь:** GEO-12, UX-01.

**Ценность:** сохранить факт прогулки и иметь возможность пройти её снова.

**DoR**

- [ ] Зафиксированы поддерживаемые клиенты и фактические ограничения фоновой геолокации; подготовлено физическое устройство для Telegram-прохода.
- [ ] Описаны отказ GPS, потеря сигнала/сети, фон/возврат, пауза и восстановление; определено обращение со сменой собаки во время записи.

**DoD**

- [ ] Старт, статус, доступные пауза/продолжение и завершение видны; переходы по разделам и слоям не прекращают запись неожиданно.
- [ ] Потерянный GPS-участок не соединён выдуманной линией; состояние и фактическая полнота записи понятны после возврата.
- [ ] Завершение сохраняет ровно одну запись; при ошибке трек остаётся доступен для повтора, а не исчезает после «успеха».
- [ ] После перезагрузки запись открывается с фактическими длительностью, геометрией и пропусками и доступна для существующего повторного использования.
- [ ] Физический Telegram-проход подтверждает поведение в фоне/при блокировке либо явно устанавливает ограничения. Обещание фоновой записи не основано на браузерной эмуляции.

**Приёмка:** физический проход с GPS-потерей/возвратом + серверный roundtrip. **Статус:** существующая функция; локальные проверки есть, физическая приёмка открыта.

### MAP-06 — Сохранённое становится следующей прогулкой

**Приоритет P2. Роли:** Design + Frontend/Backend + QA. **Зависимости:** MAP-03/04 для полного пути; существующую библиотеку проверять независимо. **Связь:** GEO-14, GEO-13.

**Ценность:** использовать уже найденное без повторного поиска и ввода.

**DoR**

- [ ] Есть подборка с несколькими местами, одно место в двух подборках, заметка, старый маршрут и недоступное место.
- [ ] Определены вход в карточку, порядок выбранных остановок, изменения оригинала и возврат.

**DoD**

- [ ] Из сохранённого открываются нужный объект и его положение; название, заметки и источник сохранены.
- [ ] Выбрать несколько мест → создать редактируемый план с теми же идентичностями/названиями и согласованным порядком; исходная подборка не меняется.
- [ ] Удаление из одной подборки не удаляет место из другой; отмена возвращает именно изменённое членство.
- [ ] Сохранённый маршрут можно повторить/изменить действующим способом; старые ссылки и права работают.
- [ ] Пустое сохранённое объясняет, откуда здесь появится результат; не выдаётся за пустую географическую область. Недоступное место сохраняет пользовательскую историю.

**Приёмка:** сохранить место → две подборки → удалить/отменить → собрать план → открыть после перезагрузки. **Статус:** переиспользование существующего, проверить передачу остановок и всю цепочку.

### MAP-07 — Предупредить в конкретной точке

**Приоритет P1 для сохранности/приватности. Роли:** Frontend/Backend + QA, Design. **Зависимости:** существующая модель предупреждений. **Связь:** GEO-01/09/10, UX-01; правила геоточности исходного беклога.

**Ценность:** не забыть опасное место и передать предупреждение только в разрешённом пользователем объёме.

**DoR**

- [ ] Описаны действующие типы, точность, видимость, изменение/удаление; выбраны два входа: с конкретной точки и с общего действия.
- [ ] Есть приватный тестовый сценарий и разрешённое окружение для проверки других видов видимости.

**DoD**

- [ ] Из выбранной точки открывается форма с этим местом; из общего действия — сначала выбор точки, не текстовый поиск по умолчанию.
- [ ] До сохранения понятны место, текст и видимость. Новый объект начинается с действующего приватного значения, не наследует случайно прошлое «По ссылке».
- [ ] Ошибка сохраняет ввод; подтверждённый результат появляется на соответствующем слое. Отмена не создаёт предупреждение.
- [ ] Доступны существующие изменение/удаление, права и точность не расширяются. Размещение этого действия не отнимает главный акцент у выбора места.

**Приёмка:** точка → приватное предупреждение → ошибка/повтор → открыть → изменить; публикационные проверки только в назначенном окружении. **Статус:** функция существует; контекст входов и регрессия требуют приёмки.

### MAP-08 — Принимать ценность, а не наличие кнопок

**Приоритет P1. Роли:** исполнитель поставки + независимый от реализации проверяющий по возможности + Product. **Зависимости:** карточки конкретной поставки. **Связь:** GEO-01, UX-01, OPS-01, REL-01.

**Ценность:** владелец получает проверенный сценарий именно по тому входу, которым пользуется.

**DoR**

- [ ] Назван состав релиза, обязательные зависимости, тестовые аккаунты, поддерживаемые клиенты и адреса входа; продуктовая приёмка не подменена дизайнерским просмотром.
- [ ] Для изменений API/поставщика записаны численные пределы запросов/задержек/ошибок и правила остановки релиза. Новые расходы не подключаются без разрешения.

**DoD**

- [ ] Пройдены применимые строки матрицы ниже; статус каждого результата — passed / failed / not run с доказательством и причиной.
- [ ] Есть запись сквозной цепочки с одинаковым содержимым, включая пустоту/ошибку/возврат; нет невидимой замены данных между шагами.
- [ ] При кодовом выпуске совпадают исходный SHA, deployment READY и health на всех поддерживаемых адресах. Отдельно зафиксирован реальный адрес входа Telegram; неизвестный адрес не считается проверенным.
- [ ] Авторизованное сохранение проверено назначенным аккаунтом; fixture, гостевой просмотр и реальный production отмечены раздельно.
- [ ] Проверены затронутые входы ассистентов и связь с «Гав» без потери контекста и расширения видимости; другие разделы не исчезли.
- [ ] Сохранены результаты, ограничения, процедура возврата и состояние новых данных при возврате. Непройденный обязательный сценарий не закрыт общим «тесты зелёные».

**Статус:** обязательный повторяемый gate; пока Backlog для будущих изменений, не новый сертификат текущей версии.

Проверка понятности отдельно от технической: дать человеку, не читавшему реализацию, задачу «найти место и подготовить следующую прогулку» без подсказок о кнопках. Записать, где он остановился, что счёл результатом и смог ли открыть сохранённое. Это качественная проверка, не статистическое доказательство успешности продукта.

## 7. Как измерять ценность

Переиспользовать действующую аналитику. Названия ниже — семантика событий для согласования с текущей схемой, не утверждение о внедрении новых событий.

- **Место использовано:** подтверждённое сохранение либо подтверждённое добавление выбранного места в черновик; просто открытие карточки — промежуточный шаг.
- **План доведён:** подтверждённое сохранение актуального маршрута; возврат — отдельное открытие этого маршрута в последующей сессии. GPX считается экспортом, не состоявшейся прогулкой.
- **Запись завершена:** подтверждённое сохранение записи; начало и нажатие «Завершить» не заменяют этот результат.
- **Снижение трения:** доля начатых цепочек с подтверждённым результатом, количество повторных поисков после потери контекста, ошибки сохранения и расчёта. Окно сессии/дедупликация фиксируются до сравнения.
- Точные частные координаты, тексты заметок и переписки в обычные события не добавляются. Нет измеренной исходной конверсии — сначала baseline; обещания роста в процентах не назначаются наугад.

## 8. Порядок работы и граница готовности

1. **Сначала MAP-01 + исследование MAP-02.** Убрать подтверждённую подмену, определить источник географической выдачи и состояния первого входа. Не объявлять этот локальный фикс завершением всего сценария.
2. **Первый полный полезный срез MAP-02 → MAP-03 → MAP-06.** Найти реальное место → сохранить → вернуться к нему. При отсутствии пригодного источника геовыдачи этот срез явно заблокирован; текстовый поиск остаётся рабочей возможностью, но не выдаётся за реализацию геообзора.
3. **Следующий срез MAP-03 → MAP-04 → MAP-06.** Место → общий план → актуальный расчёт → аккаунтное сохранение → повторное открытие. Переиспользовать выпущенное; сначала закрыть недостающую приёмку.
4. **MAP-05 и MAP-07 — самостоятельная приёмка сохранности и контекстных действий.** Подтверждённые дефекты приватности/потери данных имеют приоритет перед порядком визуальных улучшений.
5. **MAP-08 для каждого выпуска.** Готовый срез можно выпускать отдельно, но только с выполненными собственными зависимостями и честным статусом остального.

**Спецификация готова к обсуждению и декомпозиции. Реализация всех карточек не объявлена Ready:** открыты источник/численные лимиты геовыдачи, конкретные назначения ролей, связанные макеты состояний и назначенные аккаунты/физическое устройство для соответствующей приёмки. Эти пробелы не требуют снова спрашивать разрешение на уже порученную проработку; это конкретные выходы следующей подготовительной работы.

### Шаблон доказательства по карточке

- ID, версия и ожидаемый пользовательский результат.
- Выполненные DoR; открытые условия.
- Каждый критерий DoD → файл/запись/API-проверка → passed / failed / not run.
- Что переиспользовано и какие действующие возможности сохранены.
- Окружение: fixture / локальная интеграция / реальный сервис / production / физический Telegram.
- Известные ограничения и следующий шаг.
- Статус: Specified / In discovery / Ready / In progress / Ready for release / Done.
