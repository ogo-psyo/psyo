## Модель состояния до UI
- ProfileService: pet ID + canonical DogProfile/version; текущее owned bootstrap/RPC. Черновик профиля → saving → canonical receipt/conflict/error; отмена не сохраняет, ошибка не стирает ввод.
- ObservationService: ID + note + optional metrics/date. Черновик → сохраняется → record; edit/delete/restore через существующие атомарные операции. UI не присваивает сохранённый ID до подтверждения.
- DocumentService: reservation/storage/ready/deleting/deleted. Список и открытие по ID; файлы не имитируются. Ошибка/повтор сохраняют черновик в допустимых браузером пределах.
- ReminderService/WishlistService: canonical entities, scoped mutations and receipts; local guest store только для явно гостевого режима. Status done/active/deleted не менять оптимистично без отката.
- MapZoneService: existing saved-place library, route draft and canonical owner route. ID/geometry/source remain real; actual geography and attribution are not synthetic background. planning/review/saved and failure/retry use existing services.
- SocialService: candidate/request IDs, pending/accepted/declined/closed and meeting state only from service. Нельзя симулировать принятие другим человеком или отправку сообщения.
- AssistantService: current run/thread/proposal IDs, durable outcomes independent from answer text. Agent and direct UI use same domain actions.
- Navigation: current20-view key, entity ID, route stack, per-screen drafts and scroll. Back restores context. Pet switch clears pet-scoped transient state; previous owner data cannot leak.
