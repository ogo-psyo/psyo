# Проверка качества взаимодействий перед релизом

## Scope and Coverage

**Режим: full в указанной ниже границе. Версия продукта: c15d067aacccff7199e297a988e8557f1e14a995.** Это ревью текущих внутренних переходов и общей оболочки, не сравнение изменений PR и не приёмка ещё не реализованного нового дизайна.

Стек: Next16/React19/TypeScript, CSS Modules профиля + глобальные CSS/Watercolor/PaperSheet + journey-компоненты. Прочитаны AGENTS.md, IMPLEMENTATION.md, DESIGN_DIRECTION.md, HLD, предрелизные01–08 и релевантные QA-скрипты. Старый DESIGN_DIRECTION не принимается как оправдание разнородного UX. Применены better-interface и все шесть доменных навыков.

Основной вопрос на каждом шаге: **что обещает элемент → что реально открывается → какое поле/объект меняется → когда считается сохранённым → куда возвращаемся → что остаётся после ошибки/выхода**.

Runtime: локальный dev-сервер неизменённого продукта, Chromium320/390, WebKit390. Использованы существующие зависимости соседней агентной рабочей копии, Next16.3.0; новый immutable build не собирался. API полностью перехвачены Playwright: synthetic owner/pet, записи, документ и дела. Любой внешний запрос блокируется; реальные БД, карты-провайдеры, Telegram-сессии и платные сервисы не вызываются. Скрыт только индикатор Next dev, который перекрывал нижнюю кнопку; продуктовые стили не менялись. Поэтому это доказательства поведения UI на заданных ответах, **не доказательство надёжности backend и не финальный PASS-RC**.

## Verification

### Исполнено

Исходники повторно прочитаны в `wt-pso-prerelease-20260909`, код продукта совпадает с c15d067. Локальные команды:

```sh
node node_modules/next/dist/bin/next dev --webpack --hostname 127.0.0.1 --port 3259
node ../output/pso-prerelease-20260909/interaction-audit/check.cjs chromium 390
node ../output/pso-prerelease-20260909/interaction-audit/check.cjs chromium 320
node ../output/pso-prerelease-20260909/interaction-audit/check.cjs webkit 390
node ../output/pso-prerelease-20260909/interaction-audit/deep.cjs
node ../output/pso-prerelease-20260909/interaction-audit/followup.cjs
node ../output/pso-prerelease-20260909/interaction-audit/gav-retention.cjs
node scripts/qa/check-production-journey-parity-contract.mjs
node scripts/qa/check-profile-memory-production-contract.mjs
```

- Базовый проход:15 наблюдений в каждом из трёх engine/width сочетаний. OBSERVED означает «получен результат», **не «тест качества пройден»**: ожидаемо обнаружены дефекты. JS page errors в этих проходах отсутствуют.
- Дополнительные проверки: health draft/localStorage без POST, документ retry→строка истории+ошибочный toast, сохранность названия подборки при503, keyboard path. Подтверждены Q1–6/Q8–11; Q7 verified source+flag.
- В deep-проходе два неверных/преждевременных локатора оставлены UNVERIFIED в первичном журнале. Уточнённый проход использует textarea именно редактора и клик по label Гав. Старые ошибки теста не скрыты и не считаются багами продукта.
- В самих320px формах, где сняты geometry-метрики, overflow0, поля16px. Это не проверка каждой страницы из59 и не физическая iOS-клавиатура.
- Focus: Tab/Enter открывают паспорт; editor focus внутри; Escape возвращает на источник с видимой3px обводкой. Contrast-samples: белый на rgb(64,88,69)7.78:1; rgb(37,59,52) на rgb(255,254,250)11.86:1. Только измеренные непрозрачные пары.
- Source QA оба вернули `ok`. Они не выявляют смысловое несоответствие «Общительность → форма без Общительности».

### Not verified / перед RC обязательно

Реальная БД/Storage, SQL atomicity и races, две живые сессии владельцев; production-build восстановление черновика Гав; physical iOS/Android Telegram с клавиатурой/Back; все формы с VoiceOver; стекло/контраст на фото/тёмной теме; реальные запись GPS, GPX, публикация/отзыв и provider quality. Текущая review-сессия не заполняет эти клетки PASS.

Доказательства: `evidence/interaction-audit/` (JSON и сценарии); снимки и полный harness дополнительно в `output/pso-prerelease-20260909/interaction-audit/`. Product/environment/schema mutations не выполнялись. Dev-generated next-env.d.ts восстановлен после остановки сервера; служебный symlink зависимостей не является изменением продукта.

## Verdict

**Рекомендация:** не выпускать новый интерфейс поверх этих переходов. Сначала закрыть HIGH, затем принять один полный сценарий этими проверками на настоящем backend и распространить единый контракт на остальные ветки. Прежние59 семейств — реестр охвата, а не доказательство их готовности.
