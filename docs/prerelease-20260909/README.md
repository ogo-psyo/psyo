# Псё: предрелизная проработка сервиса

**Результат: проработка готова; новый релиз НЕ готов к выкладке.** Реализация, исправления найденных дефектов и приёмка release candidate — следующие отдельные этапы. Production не изменялся.

## Главные решения

1. Переносим законченные сценарии со всеми внутренними формами/ошибками/результатами, не только главные экраны.
2. «Всё» — ежедневные инструменты и история. Профиль — идентичность собаки, особенности и доступ. Дополнительные контекстные ссылки открывают тот же объект, не отдельную форму.
3. Новый дизайн поверх существующих возможностей — **R1**. Подтверждение места вторым владельцем — **R2**. Живой агент/новая память из PR29 — **R3**. Не активируем всё одним merge.
4. В R1 знакомство заканчивается реальным «предложение отправлено». «Место подтверждено» из прототипа пока не имеет backend-контракта.
5. До переноса закрываем надёжность сохранения наблюдений, профиля и файлов. Версия формы не должна менять смысл/владельца данных.

## Что обнаружено

- **Воспроизведён риск дубля наблюдения:** обработчик c15d067 с тестовым сбоем после записи выдаёт500; повтор тем же ключом создаёт вторую строку. Это локальная транспортная инъекция, не наблюдавшийся production-инцидент.
- **По коду:** обновление профиля разнесено по нескольким запросам; Storage и metadata документов могут разойтись при частичном сбое. Нужны atomic/domain-specific profile writes и устойчивый document lifecycle.
- В макете есть новое подтверждение места и память, которых нет в текущем production в показанном виде.
- Старые внутренние оболочки и глобальные CSS остаются достижимыми. Общий route contract не несёт object ID/return state для всех сценариев.
- Часть QA проверяет наличие строк/фикстуры, не фактическую БД. Счётчик тестов нельзя считать доказательством готовности backend.

## Охват

- **59 семейств экранов/форм/состояний** с ценностью, входом, результатом, исходником и решением по выпуску.
- **69 API-файлов / 99 экспортов методов**, 8 App Router страниц, 304 синтаксических декларации UI-состояний/форм. Последнее — не число экранов.
- **12 карточек работ B-00–B-11** с DoR/DoD, зависимостями, файлами и доказательствами.
- **33 сквозных приёмочных сценария**; два будущих релиза отмечены deferred.

## Проверено сейчас

Оба production адреса возвращают `c15d067aacccff7199e297a988e8557f1e14a995`; feature flags зафиксированы в `evidence/production-baseline.json`. PR29 остаётся OPEN на98785bf, без включения в аудитируемый исходник. Прочитаны ключевые сервисы/мутации/входы; подготовлен и исполнен воспроизводимый fault test неизменённого обработчика, `evidence/reproduce-observation.cjs`. Формат реестра и ссылки на исходники проверены скриптом validation.

**Не проверено сейчас:** fresh DB/Storage backup/restore, deployed migration ledger, все auth live paths, реальные SQL races, iOS/Android Telegram, actual Groq/search, immutable Vercel deployment ID и фактическая кнопка Telegram. Не изменены код продукта, БД, env, провайдеры или production. Старые результаты проверок не повышены до PASS нового RC.

## Следующий исполнимый шаг

B-00 + B-01: изолированный staging/свежая recovery-точка и атомарное сохранение наблюдений с реальной DB-проверкой. Затем B-02/B-03 и перенос первого полного сценария. Полную новую навигацию включать только после покрытия всех достижимых R1 поверхностей.

Это не просьба выбрать техническое устройство базы: решения и задачи уже сформулированы. Для отсутствующей live/device-проверки будет нужен соответствующий доступ/результат, а не повторное одобрение каждой безопасной локальной правки.
