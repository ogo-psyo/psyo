# A-01: agent → reviewed observation (locally verified candidate)

Authorized continuation 2026-09-09, after PR30. This is an explicit missing AssistantService/observation persistence task, not a database change inferred from a drawing.

## State-first contract
- Canonical record remains `pet_observations`; the ordinary UI and agent confirmation use `care_observation_atomic`.
- New private `agent_observation_drafts`: one per run, owned by the same owner/pet. Initial source is the exact current owner message, copied by the server, never generated by the model. Suggested metrics are unconfirmed until review.
- States: draft → saved (real observation ID), or draft → discarded. Repeated preparation returns the same draft and never overwrites a reviewed/saved/discarded result.
- Tool may prepare only while run is running. UI reads/reviews only after run succeeds. Cancelled/failed work cannot be confirmed. Agent itself has no confirmation tool in this slice.
- Explicit Save in UI sends reviewed note, time and optional metrics. SQL locks run/draft and writes observation+retry receipt+saved link in one transaction. Concurrent same-content saves yield one ID; different content after save conflicts. Error cannot report “saved” or destroy input. A deleted observation is not recreated by replay.
- Initial draft and saved link survive reload. Unsaved owner edits survive assistant close/reopen within the mounted application through a per-pet/run edit buffer; browser refresh returns the initial server draft. No claim that unsaved changes are cloud-saved.
- Other owners cannot read/write a draft; switching pet resets local edit buffers. Access is rechecked on every request, not derived from model args.

## User path
Message → agent prepares a note → inline text with optional metrics/date → Save → real record + Open record → same ID/text in profile history after reload. Declining the draft is reversible only by making a new request; no observation is created. No forced metrics for an ordinary text note.

## Design
Reuse approved near-white/cool-lilac connected-prototype material for this leaf, not the demo backend. One primary action, actual record/draft as object, details for optional metrics. Retain plain readable body text, accessible labels, focus/error behavior. This does not claim full five-section design transfer.

## Acceptance
SQL: other owner, cancellation, duplicate preparation/save, changed replay, injected post-observation failure rollback, deleted target, client grants/RLS.
API/tool: exact original input, input limits, mismatched run/pet, no free-provider bypass, ownership and conflict mapping.
Immutable browser build: normal note, edit, 503+same draft, close/reopen, save, exact open, reload/history, discard, width320/390, Chromium/WebKit. No paid calls. Live provider/cloud and physical Telegram remain release gates.
